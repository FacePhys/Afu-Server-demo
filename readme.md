# 蚂蚁阿福服务端设计-demo

## 预计整体通信流程

1. 客户端(安卓、ios)对请求数据进行封包，然后提供给阿福，阿福客户端上传到阿福的服务器中。
2. 阿福的服务器将接受到的请求进行转发，转发到我们的服务器中，也就是现在这个项目中进行处理。
3. 我们的服务器会提供对应的http接口，根据调用的接口进行不同的处理，处理完毕之后对阿福的服务器进行响应。
4. 阿福收到响应数据，将响应数据转发到客户端(安卓、ios)。

## 现阶段通信流程

1. 客户端(安卓、ios)对请求数据进行封包，然后直接传输到当前服务器中。这一阶段没有阿福的服务器。
2. 服务器对接口进行处理响应。响应直接回传到对应的客户端。
3. 客户端根据响应作出对应的处理。

## 接口设计

### 客户端注册请求

#### 过程描述

客户端本地生成aes密钥，并结合提前内置的rsa公钥(内置n个，选取一个随机编号的公钥)对aes密钥进行加密，并使用这个aes密钥对其他的结构体字段进行加密。最后形成一个外层明文，内部包含密文的结构体，然后发送这个完整的结构体。

#### 字段描述

> 外层字段描述

| 字段 | 说明                      | 样例                                |
| ---- | ------------------------- | ----------------------------------- |
| v    | 协议版本                  | 1                                   |
| kid  | rsa公钥编号               | 1                                   |
| type | 报文类型                  | register                            |
| ct   | 由ek+iv和密文拼接的字符串 | ebedf529617fd42a433665cfd9150d46... |

> ct字段描述

| 字段            | 说明                         | 样例                                |
| --------------- | ---------------------------- | ----------------------------------- |
| ek              | 使用rsa公钥加密之后的aes密钥 | 3MxsKrJQIGfOHvSaFYYXu7PRUL...       |
| iv              | aes的初始向量                | 8b7846d5d80d42e17c8df99e            |
| ict(剩余字符串) | 密文                         | ebedf529617fd42a433665cfd9150d46... |

> 密文解析后字段描述(ict字段)

| 字段       | 说明                                                               | 样例                             |
| ---------- | ------------------------------------------------------------------ | -------------------------------- |
| install_id | 安装编号：SDK 随机生成                                             | ebedf529617fd42a433665cfd9150d46 |
| app_key    | 我方发给客户的 App Key（阿福在 meter_open 时传入）                 | AK-demo                          |
| app_id     | 包名或 Bundle ID，SDK 自己读取                                     | com.example.app                  |
| sdk        | sdk版本                                                            | 1.1.0-beta.1                     |
| platform   | 平台：android / ios                                                | android                          |
| reset      | 新安装的原因：空 = 第一次，corrupt = 文件损坏，conflict = 编号被拒 | ""（第一次）                     |
| ts         | 生成时间（Unix 毫秒）                                              | 1792478738168                    |

### 服务端注册请求响应

#### 过程描述

根据结构体中的kid字段找到对应的rsa私钥，用这个私钥解密外层密文中对应的aes密钥字段，得到aes密钥并对密文进行解密，得到内层结构体，注册相关的信息(入库)，没有问题情况下进行成功响应，有问题则进行失败响应。

#### 字段描述

> 外层字段描述

| 字段 | 说明                                       | 样例                                |
| ---- | ------------------------------------------ | ----------------------------------- |
| v    | 协议版本                                   | 1                                   |
| type | 报文类型(ack/refused)                      | ack                                 |
| ct   | 密文字符串(使用请求上传时的ek和iv进行加密) | ebedf529617fd42a433665cfd9150d46... |

> ct字段描述(报文类为ack时)

| 字段       | 说明                              | 样例                             |
| ---------- | --------------------------------- | -------------------------------- |
| install_id | 安装编号                          | ebedf529617fd42a433665cfd9150d46 |
| seq        | 确认到第几份；回复注册时为 0      | 1（回复注册时为 0）              |
| cap_frames | 新的帧数上限 = 已确认 + 离线额度  | 2100                             |
| cap_runs   | 新的 run 上限 = 已确认 + 离线额度 | 70                               |
| ttl_sec    | 上限有效期（秒）                  | 86400                            |
| report_sec | 上报间隔（秒）                    | 60                               |

> ct字段描述(报文类型为refused)

| 字段       | 说明                   | 样例                             |
| ---------- | ---------------------- | -------------------------------- |

| reason     |  | ebedf529617fd42a433665cfd9150d46 |

### 服务端用量上报响应

#### 过程描述
和之前的解密方式一样，提取密文并进行解密，然后对相关的数据进行入库存储，计算相关的视频时长，进行相关的扣费逻辑，如果客户的剩余额度到达了预警值，对客户进行通知，如果客户额度已经没有，就使用预支额度进行扣费(额度由商务进行决定)。然后根据用户是否还有剩余额度进行响应。

#### 字段描述

响应字段和注册请求中的ack响应的字段完全相同，不会有refused类型的响应。
